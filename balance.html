Case Study 02 Consumer AI · Seed-stage

Balance Life Design

Founding-engineer build of the AI infrastructure behind an adaptive life operating system — and the Rust/WASM agent harness rebuild that followed.

Founding Engineer TypeScript · FastAPI · Rust · WASM Agent harness · Edge compute balancelifedesign.com →
01 · Problem

Zero-to-one AI infrastructure that had to survive investor scrutiny.

Balance is a seed-stage startup building an adaptive life operating system — a consumer AI product that learns from user behavior. They needed the entire AI infrastructure architected and shipped from scratch, not an LLM call bolted onto an existing app.

The fundraising round depended on the infrastructure being demonstrably production-grade, not demo-grade — while the product team still needed to iterate on agent behavior weekly without breaking determinism.

02 · What I built

The whole AI stack, then the harness it deserved.

  • AI infrastructure, zero to oneAgent orchestration, function-calling specs, prompt management, observability, and feedback loops — architected and shipped from scratch.
  • Agentic behaviorsProduction-grade agentic AI on OpenAI function-calling specifications — structured tool use rather than free-form generation.
  • Reproducibility + debuggingLangfuse for tracing and prompt versioning, with regression evals and controlled configs — agent behavior became measurable, reproducible where possible, and debuggable, not black-boxed.
  • Full-stack platformTypeScript/Next.js frontend + FastAPI backend on Heroku pipelines, with PostHog session replay and heatmaps closing the loop between product behavior and AI behavior.
  • Nimbus — the harness rebuildWhen the agent workload outgrew the TypeScript harness: a Rust→WASM edge gateway on Cloudflare Workers (auth, streaming with resume, rate limits, wake triggers) plus a Rust orchestrator in containers — session state machine, tool loop, memory on Postgres, approval gate, scheduling.
03 · Engineering decisions

Chosen for control, not fashion.

  • Determinism firstPrompt versioning and traced runs from day one — because "the agent did something weird" is only debuggable if behavior is reproducible.
  • WASM at the edgeThe gateway compiles to WASM on Workers for low-latency edge ingress; the long-running parts Workers can't hold live in containers — two compute models presenting as one system.
  • A real state machineSession and tool-loop correctness modeled as an explicit state machine, not framework magic — because resumability has to be provable, not hopeful.
  • Rebuild under flightThe TypeScript product kept serving users while the harness was rebuilt in phases — no flag day, no downtime gamble.
04 · What made it hard

No infrastructure to lean on, no definition of correct.

A founding-engineer brief on a consumer AI product means no existing infrastructure, no eval data, and no taxonomy for what "correct" agent behavior looks like — you build the definition while building the system. Streaming-with-resume at the edge is easy to demo and genuinely hard to make correct. And the rebuild had to prove itself beside a live product that couldn't afford a misstep.

05 · Outcome

Infrastructure that carried a fundraise.

The AI stack I shipped was the demonstrable technical asset during fundraising — the infrastructure helped secure seed funding and onboarded 1,000+ early-access users. The Nimbus harness rebuild is the second act: the same system, re-architected in Rust for the reliability envelope the workload now demands.
